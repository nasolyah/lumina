# Spatial PDF Mapper — MVP и что доделать позже

Статус: **прототип Этапа 1** (layout-aware извлечение + spatial-рендер).
Цель — сделать правдой строки таблицы «Content Handling» и «Primary Interface»:
документ виден «как у автора», текст-сниппеты дословные, ничего не переписано.

## Что сделано в MVP

- Бэкенд-извлечение `ingest.py` (прототип): PDF → манифест документа.
  - `pdfplumber` (MIT) — текст-блоки с bbox-координатами, дословно.
  - `pypdfium2` (Apache/BSD) — рендер страниц в WebP (сохранение вёрстки).
  - Лицензионно-чистый стек (без AGPL-PyMuPDF).
- Манифест `schema_version=2`: `pages[] + blocks[]`.
- Фронт-прототип: рендер манифеста на холсте с зумом/паном (страницы + оверлей блоков).

## Заложенные лимиты (риски памяти/объёма — уже в MVP)

- `MAX_PAGES = 30` — режем длинные PDF.
- `RENDER_DPI = 130` — достаточно для экрана.
- WebP q80 вместо PNG — в разы компактнее.

## Что доделать позже (DEFERRED)

### 1. Хранилище картинок — Supabase Storage (сейчас data URL)
MVP embed'ит страницы как base64 data URL прямо в манифест — быстро, но раздувает JSON
и не годится для прода. Позже:
- отдельный bucket + signed URLs;
- **перегенерация из PDF по запросу** (кэш с TTL) вместо вечного хранения PNG — Storage не пухнет;
- удаление артефактов при удалении чата; квоты по тарифу (через существующий `usage_counters`).

### 2. Async-обработка (риск памяти/таймаутов Render)
Сейчас извлечение синхронно. Для больших PDF:
- `/api/ingest` ставит job → отдаёт `job_id` → фронт поллит статус;
- **ленивый постраничный рендер** (страница рендерится, когда доскроллили), не вся пачка.

### 3. Извлечение фигур/чартов/формул (Этап 2 — «Visual Elements»)
- растровые картинки: bbox из pdfplumber → вырезать → Storage;
- векторные чарты/формулы: **рендер области страницы по bbox** (не «чистое» извлечение);
- классификация типа (chart/equation/image) — только метка, не влияет на извлечение;
- связывание фигур с текстом по подписям («Рис. 2», «Figure 3») → `links[]`.

### 4. Сканы без текстового слоя
- детект: страниц много, блоков ноль → скан;
- деградация: layout-режим на рендере страниц (документ виден, но без блоков);
- OCR (Vision/Tesseract) — опциональный апгрейд по флагу, НЕ в MVP.

### 5. Приватность — правило «пиксели не уходят в Gemini» (решить до Этапа 2)
- текст-блоки → в модель (как сейчас);
- **картинки страниц/фигуры по умолчанию НЕ уходят** в модель; связывание — по подписям/ссылкам, не по пикселям;
- визуальный анализ картинок — только по явному opt-in;
- снимает спорный пункт «Приватность данных» на лендинге — **только если реально соблюдается в коде**.

### 6. Совместимость со старыми чатами
- `schema_version` в записи чата: старые (`source_text`+`mindmap`) = v1, новые (манифест) = v2;
- фронт по версии выбирает рендер: v1 → текущий «граф понятий», v2 → spatial;
- ленивый апгрейд v1→v2 при повторном открытии (если PDF доступен) — опционально.

### 7. Интеграция в прод (после проверки прототипа)
- перенести `ingest.py` в `lum_backend/` как модуль;
- **requirements.txt**: `pdfplumber`, `pypdfium2`, `Pillow` — потребует redeploy Render (проверить память воркера);
- новый эндпоинт вместо/рядом с `/api/extract`;
- граф (пилюли/кривые/сворачивание) переиспользуем как индекс-надстройку поверх реального контента, не выбрасываем.

### 8. Качество группировки блоков
Текущая эвристика строк/абзацев простая (порог вертикального разрыва + высота глифов
для заголовка). Позже: колонки (multi-column layout), таблицы, списки, переносы.

## Находки с реального прогона (Cambridge 9709 qp, 20 стр., 2.3с, манифест 1.76 МБ)

- ✅ **Заголовки детектятся** на живых шрифтах («Cambridge International AS & A Level» → heading).
  На синтетическом моношрифте не срабатывало — это ограничение теста, не движка.
- ✅ **Вёрстка сохранена точно**: логотип, поля кандидата, штрихкод, таблицы — в картинке страницы.
- ⚠️ **Математика в текстовом слое коверкается** (подтверждено):
  - надстрочные степени схлопываются: `x²`→`x2`, `(1−4x)⁶`→`(1-4x)6`;
  - выносные формулы/дроби извлекаются вперемешку и не по порядку:
    `7tanθ/cosθ + 12 = 0` → `7tani ... +12 = 0`; `f⁻¹(x)` → `-1(x)...f`.
  - **Но картинка страницы рендерит математику идеально.** Вывод:
    - для матем-блоков доверять **картинке региона** (Этап 2), а не тексту;
    - матем-текст из блоков **не отправлять в Gemini как есть** (мусор на входе);
    - в spatial-виде читатель и так видит верную формулу на картинке страницы.
- ⚠️ **Шум пустых страниц**: листы для ответов дают сотни блоков-точек (`....`),
  «BLANK PAGE», «Additional page». Нужен фильтр: выкидывать блоки из повторяющихся
  пунктиров и служебные страницы (или помечать страницу как «пустой ответный лист»).
